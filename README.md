# PostPipeline

PostPipeline - это высокопроизводительный модуль для сбора и обработки данных из открытых источников. Проект демонстрирует применение различных моделей конкурентности в Python для решения специфических задач: асинхронной работы с сетью (I/O-bound), параллельных вычислений на процессоре (CPU-bound) и многопоточного ввода-вывода.

## Как начать?

Клонируем репозиторий:

```bash
git clone https://github.com/aleksaphp/pipeline_project.git
```

Установка:

```bash
python -m venv .venv
source .venv/bin/activate        # macOS / Linux
# .venv\Scripts\activate         # Windows
pip install -r requirements.txt
````

Запуск:

```bash
python main.py
```

## Architecture Choices:

Пайплайн разделён на три стадии, и для каждой выбран свой инструмент конкурентности — под характер нагрузки.

1. Сеть → asyncio
   Загрузка постов — I/O-bound задача: почти всё время тратится на ожидание ответа сервера, а не на CPU. asyncio
   позволяет держать сотни одновременных запросов в одном потоке, переключаясь между ними

2. Расчёты → multiprocessing
   Обработка постов — CPU-bound, threading бесполезна из-за GIL, а asyncio дает прирост только, когда задача ждет, тоесть для I/O-bound задач. multiprocessing же запускает отдельные процессы
   со своим GIL, они работают параллельно на разных ядрах.

3. Сохранение и логирование → threading
   Запись результатов в файл — снова I/O-bound, но asyncio здесь был бы избыточен, поскольку файловый I/O в Python не
   даёт настоящей асинхронности без сторонних библиотек. Поэтому мой выбор пал на threading
